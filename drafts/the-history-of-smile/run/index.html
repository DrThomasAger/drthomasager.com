Run in Smile, a Task Carried Live by Many Agents and a Person

In THE MAP, a run is a task carried live by many agents and a person, each agent a separate process with its own context, the orchestrator reading the real time logs and directing everything.

Dr Thomas Ager18 October 20264 min read

(claude wrote this for me)

THE MAP names the agents of a run. A script writer, an orchestrator, and identifiers of requirements, win conditions, failure cases and their solutions. An optimiser reviews all of their outputs and earlier runs, makes a hypothesis for going faster and rewrites the script. A knowledge agent keeps the fastest ways, and a general script agent keeps every reusable script. A person interrupts any script at any time and the run resumes by itself four seconds later. Every human action is measured, and when a person's way is faster it becomes the new fastest way. This is the decomposition of Transfer running, the local agents with minimal context and the foundation model carrying the remainder.

The run began as one prompt handed to an agent. On 12 September 2026, “Anything you want done in any game can now be done with one prompt”.1

The script writer, the orchestrator reading the live logs, and the identifiers of requirements, win conditions and failures, the agents of a run as THE MAP has it.

The script writer and the one who reads the real time logs are different. The real time log reader and orchestrator is the main controlling agent (foundation model). There is also a requirements identifier, win conditions identifier, failure case identifier, as well as solutions to failure cases identifier, and an optimiser that reviews all of the outputs of those and the previous runs and makes a hypothesis to test for it to go faster, rewrites the script. All the scripts and activity on the game can be interrupted at any time by a human and auto resumes after four seconds. They can also be interrupted by an actor the main orchestrator can create. This actor that they can create interrupts the current actions to do activities that improve the run based on it. Any human activities or human activities are interpreted real time and also measured. If the measurement is faster or something is demonstrated that the knowledge agent, who is always aware of the fastest ways to do things, who works with the general script agent who keeps all re-usable scripts that can be applied to multiple scenarios.

Questions

What is a run in Smile?

A task carried live by many agents and a person. Each agent is a separate process, and an orchestrator reads the real time logs and directs the rest.

What happens when a person interrupts a run?

In THE MAP, the person can take over any script at any time, every difference is measured, and the run resumes by itself four seconds later. A faster human way becomes the new fastest way. Manual takeover with its timing compared is part built today.
